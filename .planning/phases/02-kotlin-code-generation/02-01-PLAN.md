# Plan 02-01: Emit *AsyncResponse Data Classes

**Phase:** 2 — Kotlin Code Generation
**Requirement:** CODEGEN-01
**Estimated size:** ~50 lines production code, ~120 lines tests

---

## Goal

Extend `MethodProcessor` to emit a typed `*AsyncResponse` data class alongside the existing
`*Request`/`*Response` classes for methods whose `domain.Method.asyncResponse` is non-null and
resolves to an `ObjectSpec`. Extend `MethodClassNames` with a third field. Add a unit test and
smoke test to confirm the behavior.

## Tasks

### Task 1 — Extend `MethodClassNames` (MethodProcessor.kt:169)

Replace the 2-field data class with a 3-field data class:

```kotlin
data class MethodClassNames(
    val requestClassName: ClassName,
    val responseClassName: ClassName,
    val asyncResponseClassName: ClassName?,
)
```

`asyncResponseClassName` is `null` when the method has no `asyncResponse` block or its `typeSpec`
is not an `ObjectSpec`. See decision D-02.

### Task 3 — Add `createAsyncResponseClassDefinition()` (MethodProcessor.kt, after line 411)

Mirror `createResponseClassDefinition()` exactly:

```kotlin
private fun createAsyncResponseClassDefinition(
    asyncResponse: Response?,
    asyncResponseClassName: ClassName?,
): TypeSpec? {
    if (asyncResponse == null || asyncResponseClassName == null) return null
    return when (asyncResponse.typeSpec) {
        is DomainTypeSpec.ObjectSpec -> objectProcessor.processObjectToTypeSpec(
            asyncResponseClassName,
            asyncResponse.typeSpec,
            useFutureProofEnum = true,
            forceTopLevel = false,
        )
        else -> null
    }
}
```

### Task 6 — Create smoke test YAML fixture

Create `src/test/resources/async-smoke-test.yaml` covering all three D-05 cases:

```yaml
title: Async Code Generation Smoke Test
service:
  common:
    response objects:
      - name: AsyncJobResponse
        fields:
          - name: dummy
            long name: dummy
            type: int
  methods:
    - id: 1
      name: submitJobTypeRef
      method: POST
      authentication required: false
      response:
        typeref: AsyncJobResponse
      asyncResponse:
        type: object
        fields:
          - name: result
            long name: result
            type: string
    - id: 2
      name: submitJob
      method: POST
      authentication required: false
      response:
        type: object
        fields:
          - name: job
            long name: job
            type: int
      asyncResponse:
        type: object
        fields:
          - name: result
            long name: result
            type: string
    - id: 3
      name: getStatus
      method: GET
      authentication required: false
      response:
        type: object
        fields:
          - name: status
            long name: status
            type: string
```

**Why this works:**
- `AsyncJobResponse` is defined in `service.common.response objects`, making it a referencable type that passes the second validation pass
- Method 1 (`submitJobTypeRef`) — D-05 Case 1: `response.typeref == "AsyncJobResponse"` → `responseIsAsync()` returns true (it's in the default `asyncCapableResponseTypes` set), so VALID-04 does not fire; `asyncResponse` is ObjectSpec → generates `SubmitJobTypeRefAsyncResponse`
- Method 2 (`submitJob`) — D-05 Case 2: `response` has a `job` field (satisfies VALID-04) + `asyncResponse` is ObjectSpec → generates `SubmitJobAsyncResponse`
- Method 3 (`getStatus`) — D-05 Case 3: no `asyncResponse`, no `job` field (no VALID-03 warning) → no `GetStatusAsyncResponse`
- All methods have `id` (satisfies "must have id or path")
- All fields have `long name` (required by default `ValidationOptions`)
